## 2. Use WireGuard (If Your Provider Supports It) (5 min)

WireGuard is lightweight, modern, and usually more stable than OpenVPN.

1. **Install WireGuard** on your OS (desktop, phone, router).  
   *Windows:* `https://www.wireguard.com/install/`  
   *Linux:* `sudo apt install wireguard`  
   *Router:* many DD-WRT/Asus firmware have WireGuard modules.
2. **Get a config** from your VPN provider.  
3. **Add PersistentKeepalive** (for LAN or NAT)  
   ```ini
   [Interface]
   PrivateKey = <your_private_key>
   ListenPort = 51820
   
   [Peer]
   PublicKey = <peer_public_key>
   Endpoint = <vpn.server.ip>:51820
   AllowedIPs = 0.0.0.0/0
   PersistentKeepalive = 25
   ```
4. **Start the interface** (`wg-quick up <name>`).  
5. **Verify**: `wg show` → should show a steady transfer and a `latest handshake` timestamp.

**Result:** Even if the underlying UDP channel hiccups, the keep‑alive keeps the NAT mapping alive so the tunnel doesn’t tear down.

## 3. Configure Your Device & Network

### A. Router‑Level VPN (Optional but Recommended)

- **Why?** All traffic from your home network goes through the VPN, so you don’t have to select a VPN app on every device.  
- **How?**  
  1. Log into your router’s admin.  
  2. Find “VPN Client” section (look for “OpenVPN” or “WireGuard”).  
  3. Upload the provider’s config file.  
  4. Enable “Kill Switch” if available.  
  5. Reboot router.

### B. Split‑Tunneling

If you need to browse the local Cuban network for other services, enable split‑tunneling for the platform’s domain or IP.

- **OpenVPN**: add `route <platform_ip> 255.255.255.255 net_gateway` to the client config.  
- **WireGuard**: remove the IP from `AllowedIPs` for the platform and add it manually.

### C. Ensure No DNS Leaks

- Switch to a provider’s DNS (e.g., 10.8.0.4 for NordVPN) or use a public DNS like Cloudflare 1.1.1.1 with “DoH” (DNS over HTTPS).  
- In WireGuard config, add `DNS = 1.1.1.1, 1.0.0.1`.

## 4. Test the Stability

1. **Speed Test** – use `speedtest.net` or `fast.com` while connected.  
2. **Ping Test** – `ping -c 30 8.8.8.8` → steady round‑trip times.

## 5. If It Still Drops

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| **VPN disconnects after 20 min** | NAT timeout on ISP router | Use `PersistentKeepalive = 25` (WireGuard) or `ping-timer` (OpenVPN). |
| **VPN fails to start** | Local firewall blocking ports | Open UDP 1194/TCP 443 or use the provider’s “stealth” server. |
| **Connection goes to local IP** | DNS leak or mis‑routing | Force DNS, double‑check `AllowedIPs`/routing. |
| **Slow speeds / high latency** | ISP throttling | Switch to a “stealth” server, use TCP 443, or use a dedicated IP. |
| **Cuban ISP blocks VPN** | Deep packet inspection | Use a VPN with “obfuscation” or “stunnel” (TLS‑wrapped). |
| **Platform blocks US IPs** | Geo‑restriction | Use a “smart DNS” or a proxy that mimics a local IP. |

## 6. Backup Plan (If VPN Is Unreliable)

1. **Remote Desktop to a US VPS**  
   - Spin up a cheap VPS (DigitalOcean, Linode) in Florida.  
   - Install RDP or VNC; log in from Cuba.  
   - Use the VPS to access the platform; close the RDP session when done.

2. **SSH Tunnel**  
   - `ssh -L 8080:platform.com:80 user@vps_ip`

   - SSH is often less likely to be blocked.

3. **Smart DNS Service**  
   - If the platform only blocks IPs, a Smart DNS can trick it into believing you’re in Miami.  
   - Providers: **SmartDNS Proxy**, **Unlocator**, or **OpenDNS**.
